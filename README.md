# 知行课堂作业管理系统

基于 Flask、Flask-Login、SQLAlchemy 和 SQLite，已完成规划中的三个开发阶段：注册登录、课程与教学班、作业发布与上传、提交版本、评分与退回重做、成绩册、个人成绩、站内通知、统计和 CSV 导出。

## 启动

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

已有 `.venv` 时直接执行 `.\.venv\Scripts\python.exe app.py`。浏览器打开 http://127.0.0.1:5000 。修改代码后需重启正在运行的旧进程。

数据库和 uploads 目录自动创建，重启后数据保留。默认没有预置账号。

## 最终阶段演示

1. 教师创建课程、教学班；学生用加入码加入班级。
2. 教师发布作业，学生在“通知”中看到新任务；加入班级前已发布的作业会在加入时补发通知。
3. 学生提交两次，在详情查看“当前有效版本”和折叠的“历史版本”；教师默认只批改当前版本。
4. 教师评分后，学生在“通知”和“我的成绩”查看分数、评语、课程平均分及成绩变化。
5. 教师填写退回原因和未来的重交截止时间，学生收到重做通知。即使原作业已截止，该学生也能在获准期限内重交；其他学生继续遵守原截止时间。
6. 教师在“成绩与统计”按课程、班级或作业查询成绩册，查看提交率、未交人数、平均分、最高最低分、分数分布，并导出 CSV。

所有成绩和待批改统计以每位学生的最新版本为准，历史版本保留文件、成绩和反馈。重新提交后等待重新评分；退回的成绩不计入平均分。平均分只计算当前已评分作业，包含 0 分，未提交不自动折算为 0 分。CSV 使用 UTF-8 BOM，可用 Excel 打开。

## 细节完善

- 教师在“作业详情 → 作业管理”修改标题、要求和截止时间，或归档、恢复作业。归档保留历史附件与成绩，停止提交和批改；在作业列表点击“已归档作业”查阅。
- 已退回的当前版本提供“延长重交期限”，原期限过期后也可延期，须填写原因；学生收到通知。
- 点击导航中的姓名进入“个人资料”。新学生注册需填写姓名与唯一学号；已有账号可自行补全。教师名单、成绩册和 CSV 同时展示身份信息。
- 作业详情可展开“批改与期限调整记录”，查看历次评分、原评语、修改后的评语、操作教师和时间。升级前已有成绩不伪造历史操作记录。
- 作业列表每页 12 项，筛选在数据库中完成并保留分页条件；状态批量查询，新增提交复合索引。

首次启动本轮完善后的代码时生成 `homework.db.stage3.bak`，增加身份字段、归档状态和审核记录表。现有账号身份字段默认为空，原有数据继续保留。

真实浏览器验收使用隔离演示数据库，见 `scripts/browser_acceptance.cjs`。验收报告及截图说明见 [细节完善与验收报告](细节完善与验收报告.md)。

## 第二阶段数据升级

首次启动最终阶段代码时，自动生成 `homework.db.stage2.bak`，新增通知表和提交审核字段。保留原账号、课程、班级、加入码、提交记录、文件及成绩；重复启动不会重复迁移。备份只包含数据库，上传文件需与 `uploads` 目录一并保管。

所有修改操作（包括退出登录）使用带 CSRF 令牌的 POST 表单；刷新旧页面后再操作。默认会在 `instance/secret.key` 生成并保留随机会话密钥，也可通过 `SECRET_KEY` 环境变量指定。

## 第二阶段演示

1. 注册教师和学生账号，教师登录后进入工作台。
2. 教师在“课程管理”中创建课程，进入课程详情创建教学班，记录加入码。
3. 教师在“作业”页面展开“发布新作业”，选择对应课程和教学班，填写要求并设置未来的截止时间。
4. 学生登录后在“我的课程 / 加入班级”中输入加入码。加入前不能查看或提交该班级作业。
5. 学生通过关键词、课程、班级或状态筛选作业，在详情页上传文件。
6. 教师在工作台查看待批改任务，在作业详情查看班级提交进度、下载文件并评分；学生查看成绩与评语。

所有新增截止时间和提交时间统一使用北京时间。截止后禁止再次提交。未提交的任务显示“待提交”或“已逾期”；已提交的任务显示“已提交 · 待批改”或“已提交 · 已评分”。学生还可以按“已提交”统一筛选这两种状态。工作台提醒未来 3 天内到期且尚未提交的作业。

## 第一阶段数据升级

首次启动第二阶段代码时，会自动创建新增表并补齐旧表字段，不删除原账号、作业、文件和成绩。更改旧表之前自动生成 `homework.db.stage1.bak` 数据库备份。

历史作业按发布教师归入“第一阶段历史课程 / 第一阶段历史班级”，原提交学生自动加入相应班级；其他学生需通过加入码加入后才能查看。教师可以修改历史课程名称和简介，并在课程详情查看历史班级加入码。历史作业没有截止时间，继续保留原有行为；新发布的作业必须关联课程、教学班并设置未来的截止时间。重复启动不会重复生成历史课程或成员。

## 验证

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

测试使用独立的临时 SQLite 数据库与上传目录，不改动现有业务数据。覆盖第一、第二阶段迁移与备份、原有流程、版本与过期评分拦截、退回重交、成绩统计、CSV、通知隔离、CSRF、非法附件及异常回滚。详细规则与演示流程见 [第三阶段开发说明](第三阶段开发说明.md)，前期功能见 [第二阶段开发说明](第二阶段开发说明.md)。

请求总大小限制为 20 MB，支持常用文档、图片、代码、压缩包，并进行扩展名和基础文件头检查。教师仅能批改自己发布的作业，学生仅能下载自己的提交。

按照规划，Anaconda 环境配置留到系统全部完成后，经确认再进行，当前继续使用原有 `.venv`。

本项目为课程演示，注册页允许自行选择教师身份。公开部署应限制教师注册，设置 SECRET_KEY 环境变量，并使用正式 WSGI 服务和 HTTPS。
